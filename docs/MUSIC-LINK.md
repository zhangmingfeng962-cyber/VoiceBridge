# 独立音乐链接

当 QQ、微信或游戏的语音处理无法关闭时，可让音乐经过独立链接。朋友继续在原来的软件里与你说话，另开收听页面播放音乐。音乐不再进入那款软件的麦克风处理，因而不受该语音通道的降噪和自动增益影响。

这不是反向降噪，也不会修改目标软件。网络、浏览器、操作系统增强和耳机仍会影响听感；不保证零断流、与本地完全一致或端到端低于 100 ms。

## 分享者

1. 在 Windows 11 x64 上打开新版 VoiceBridge。独立分享不需要安装 VB-CABLE，也不需要开启真实麦克风。
2. 在上方“独立音乐链接”区域选择 QQ音乐、网易云音乐或酷狗音乐，正常播放音乐。此区域的来源独立于下方语音混音来源。
3. 保留“开始时关闭下方语音频道的音乐”，点击“开始独立分享”。如果下方原本正在传音乐，会关闭那一路音乐；原本开启的人声会继续传送。若原本只开了音乐，则停止原虚拟混音。
4. 默认创建临时互联网链接，首次会从 Cloudflare 官方 GitHub 下载约 53 MB 的 `cloudflared`，验证固定 SHA-256 后运行。无需账号、管理员权限或路由器端口映射。下载失败或网络不通时会提示；不要把 `127.0.0.1` 链接发给朋友。
5. 出现“临时收听链接已建立”后，点击“复制朋友收听链接”，把完整链接发送给想邀请的人。
6. 你的人声继续通过原来的语音软件或 VoiceBridge 的人声开关传送。独立链接始终不发送麦克风。

首次获取链接需要访问 GitHub 和 Cloudflare。临时服务用于测试，没有持续可用保证，在部分网络无法建立或访问。程序不会把“获得域名”当作成功：它会再检查 HTTPS 服务能否返回本次本机服务的健康标识，通过后才提供复制按钮。这仍不能代替朋友网络上的验收。

## 收听者

1. 用新版桌面 Edge 或 Chrome 打开完整链接；无需安装 VoiceBridge，不需要允许麦克风。
2. 点击“开始收听”。浏览器要求主动点击后才能播放声音。
3. 先用默认 240 ms 缓冲；网络好时可改 120 ms，偶发抖动可试 480 ms。数值是播放队列目标，不是总延迟。
4. 调整页面的“收听音量”。页面不做降噪、回声消除、自动增益、响度归一化或人声门限。
5. 保留原来的 QQ / 微信 / 游戏通话。建议用耳机，避免页面音乐从扬声器串进真实麦克风。

推荐桌面 Edge / Chrome。其他支持 AudioWorklet 的浏览器可能可用，但未逐个验收。手机锁屏、切到后台或省电模式可能暂停网页音频，需要回到页面点继续。

## 停止与托盘

- “停止独立分享”只停止链接，不关闭原来的人声通话。
- 主界面或托盘的“全部停止”停止虚拟混音和独立链接。
- 关闭 / 最小化主窗口会收起到托盘，继续分享；托盘菜单显示链接是否开启。
- 托盘“退出程序”关闭本机服务、收听连接和本次启动的临时连接组件。
- 每次开始生成新的随机收听密钥；停止后旧链接失效。重新启动软件或开机自启动都不会自动分享。
- 下方人声 / 音乐按钮和 Ctrl+Alt 快捷键仍只控制原来的虚拟麦克风通道；收听页面有自己的音量。需要停止独立分享时，用专用按钮或托盘“全部停止”。

本机试听会播放第二份音乐。建议把接收页音量先设为 0 观察状态，再用较低音量试听；不要把整个浏览器进程送入原音乐捕获源。

## 音质与带宽

采用 48,000 Hz、双声道、IEEE float32 PCM，10 ms 一包，WebSocket 传输，不使用有损语音编码。普通有限样本在传输封包中保持原位值；非有限值会转成静音，接收端将超出满幅的值限制在 [-1, 1] 以免无界输出。源过载仍会失真，请关闭过大的 EQ / 音效增益。

每人原始音频约 3.072 Mbps（384 KB/s，约 1.38 GB/小时），另有 WebSocket / TLS 等开销；最多 8 人，分享者上行随人数增加。本机试听也占用一个收听位置。请留足带宽；增大缓冲不能解决持续网速不足。

接收端使用固定音量与有界环形缓冲；通过很小的播放速率校正跟随双方时钟漂移，断流时淡入淡出并重新缓冲。因此“未压缩传输”不等同于最终音频设备逐位输出或完全相同听感。不能保证本地 / 广域网总延迟小于 100 ms。

慢连接不会阻塞捕获或无限积压旧音频：发送队列达到上限会断开该连接，接收页尝试重连并清空旧队列。页面显示缓冲耗尽、序号中断和过期队列计数；这些不是平台通话质量的统计。

## 链接与隐私

收听密钥为每次生成的 256 位随机值，放在 URL 的 `#` 后；普通 HTTP 页面请求不会把片段发送给服务器。接收页通过 WebSocket 首个消息提交密钥，认证通过才收到音频。最多 8 个认证收听者，握手有超时和数量限制。

持有完整链接的人就可以收听，不区分身份；请只发给指定朋友，不要公开贴到群或仓库。点击停止可撤销所有人的访问。本版本不提供单独踢人和账号系统。

临时链接使用 HTTPS / WSS，但 Cloudflare 在边缘终止 TLS，音频经其服务转发，**不是端到端加密**。程序不录制或保存分享音频，不含第三方网页脚本、分析器，也不向链接发送麦克风、游戏 / 队友声音、设备清单或本地文件。

本机服务只监听 `127.0.0.1` 随机端口，提供接收页、静态脚本、健康检查和经认证的音频 WebSocket，没有目录浏览或远程控制接口。不修改防火墙、不安装系统服务、不注册其他软件的自动启动。临时连接组件由任务对象管理，程序退出 / 崩溃时关闭。

## 使用已有固定 HTTPS 地址

临时服务不适合需要可靠长期可用的场景。你可以接入自己管理的 HTTPS 反向代理或固定 Cloudflare Tunnel：

1. 取消“创建临时互联网链接”，开始独立分享。
2. 展开“连接统计与固定 HTTPS 地址”，查看当前本机监听地址，例如 `http://127.0.0.1:12345/`。
3. 将自己的 HTTPS 根域名转发到该地址，转发 `/audio` 的 WebSocket 升级，禁用缓存和响应缓冲；建议设足够长的 WebSocket 读超时。不要配置转发到别的本地服务。
4. 输入根地址，例如 `https://music.example.com/`，点击“使用固定 HTTPS 地址”，复制邀请链接。
5. 软件只检查地址格式，不配置或验证你的外部代理。请先从另一个网络测试。每次重开分享本机端口可能变化，需要调整代理；密钥也会改变。

NGINX 示例，需自行准备域名、有效 HTTPS 证书和到本机的可信连接；`127.0.0.1` 指代理所在主机，不能直接指向另一台电脑：

```nginx
location / {
    proxy_pass http://127.0.0.1:12345;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```
