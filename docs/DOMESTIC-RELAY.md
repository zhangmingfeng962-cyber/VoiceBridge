# 国内中继与桌面配置

v0.8.2 修正了桌面 EXE 未读取到开发工具隔离目录中配置时，错误地回退到临时隧道的问题。

## 桌面使用

1. 从系统托盘退出旧版；点 × 只会收起，不会退出。
2. 把本机专用便携包解压到固定文件夹，保留 EXE 和同目录的 `VoiceBridge-sender.vbrelay`，双击新版 EXE。
3. 首次启动会将可解密的便携配置保存到当前桌面程序自己的 Windows 用户目录（已有配置不会自动覆盖），界面会显示当前中继地址及配置来源。如果没有读到正确地址，点击“导入中继配置”，选择包中的 `.vbrelay` 文件。
4. 点击“检查中继连接”。该操作只校验本机凭据可解密和健康接口，不采集声音或创建房间。检查通过后再创建房间；发送权限在创建时验证。

`.vbrelay` 是当前 Windows 用户 DPAPI 保护的发送配置，换 Windows 账户或电脑不可解密。不要公开发送该文件或本机专用便携包。公共 EXE 和源码没有附带任何账户的发送权限。

导入前会验证地址、格式及 DPAPI 凭据；失败保留原配置，成功替换前备份为 `.previous`。未配置跨网服务时不会自动开启捕获或尝试临时隧道。创建失败会释放本次音频捕获和本机监听端口，可以直接重试。

## 部署到国内容器平台

中继是 Node.js 22+ 服务，可以运行在提供 HTTPS、WebSocket 升级和长连接的国内容器平台。`relay/Dockerfile` 使用锁定摘要的官方 Node 镜像；配置如下：

- 1 个实例，起点 0.1 CPU、256 MiB 内存，监听 `0.0.0.0:3000`。
- 环境变量 `PORT=3000`、`PUBLIC_ORIGIN=https://实际公网根地址`、`PUBLISH_KEY_HASH=发送密钥的SHA256`。
- `PUBLIC_ORIGIN` 须和 HTTPS 地址完全匹配；它也用于验证房间语音的 WebSocket Origin。
- HTTPS 入口须支持 GET/POST/PUT/DELETE、至少 160000 字节请求和 WebSocket Upgrade。不要缓存音频接口。
- 健康检查 `/health` 应返回 `ready:true` 和 `voiceRooms:true`；HTTP 健康检查不能单独证明音频及语音可用。
- 音频及房间仅在内存中；必须保持单实例，不把同一房间随机分发到不同进程。

Sealos 杭州节点支持这类部署。账户的注册试用余额不是永久免费的套餐：计算资源按运行时间扣减，流量另计，余额用完需停用或由用户自行决定后续方案。本文不承诺免费额度、赠送政策或未来价格。

未压缩音乐每位收听者约 1.38 GB/小时，另加语音和协议流量。请在费用中心查看余额及用量；不使用时在应用管理暂停服务，之后需要分享时再启动。不要把基础资源每日预估当作包含流量的总费用。

配置发送者时可运行：

```powershell
./relay/configure-sender.ps1 -Origin https://你的国内中继根地址 -ExportPath ./VoiceBridge-sender.vbrelay
```

脚本只输出可放入服务器的验证散列，不显示发送密钥。导出的 `.vbrelay` 可放在 EXE 旁，或从软件界面导入。开发工具及商店应用可能把 AppData 写入隔离目录，向自己工具目录写入配置不等于桌面程序也能读取；应交付显式便携配置，并在桌面程序中检查配置来源。
