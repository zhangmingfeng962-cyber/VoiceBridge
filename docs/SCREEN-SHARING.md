# 屏幕共享 0.10.0

本版新增独立视频通道。原有音频协议 3、成员音量和客户端音源采集保持兼容。页面必须由新版房间服务提供，单独换 EXE 不会升级服务器网页。

## 使用方式

1. 在新版房间控制页点击“共享软件窗口／桌面”，从系统选择器选择软件窗口或显示器。每次开始和更换来源都需要主动确认；入房不会自动共享屏幕。
2. 同一房间只能有一个共享者，任何成员都可以发起。其他成员自动观看，也可以停止观看、重连、放大、全屏或调整适应方式。
3. 暂停画面会移除发送器上的视频轨道，观看端显示不透明占位画面；恢复后继续。取消更换来源保留原画面。关闭控制页、离房、撤销捕获权限或共享者断线会释放占用。
4. 画面采集不请求系统音频。Windows 配对控制页复用已有的程序音源共享；网页模式可另外共享其他浏览器标签页音频。共享声音与音乐是同一条高质量音频通道，开关、音量同步，避免发送两份。接收端的“共享者程序声音”与成员音乐音量同步。
5. 画面暂停或结束不会改变独立的人声和音乐开关。需要结束声音时关闭“共享声音”；离房会停止本机采集。

## 画质与连通性

- 默认均衡 1280×720 / 30fps，目标最高 1.4Mbps/连接；流畅 854×480 / 15fps、700kbps；清晰最高 1920×1080 / 30fps、2.4Mbps。设备和网络可能导致实际参数更低。
- `SCREEN_VIDEO_BUDGET_BPS` 默认 5,000,000（允许 128,000–8,000,000），按当前共享房间和观看人数分摊。即使关闭自动调整，仍受总预算和浏览器拥塞控制限制。
- 自动模式在网络往返、丢包、可用发送带宽或本机音频等待恶化时降低视频码率、分辨率和帧率，平稳后缓慢恢复。无法保证互联网完全不卡顿。页面显示网络往返时间，不将其冒充端到端画面延迟；500ms 是待跨网测量的目标。
- 视频使用 WebRTC，默认 ICE 优先选择直连，配置有效 TURN 后可使用中继。不配置 TURN 时明确提示“仅可尝试直连”，不会宣称公网兜底已就绪。
- 受保护视频、独占全屏游戏、某些最小化窗口可能没有可捕获画面。实际 Windows 10/11、多显示器和不同显卡仍需人工选择源进行验收。

## 服务器接入

`STUN_URLS` 是逗号分隔的 STUN 地址；`TURN_URLS` 是 TURN/TURNS 地址；`TURN_SHARED_SECRET` 仅保存在服务器，至少 32 字符。TURN 地址与密钥必须同时配置。服务器向经过房间身份验证的网页成员或当前配对控制页签发 10 分钟临时凭据；网页每四分钟刷新并在需要时重连。密钥不进入 EXE、邀请或网页资源文件。

准备及启用脚本为 `scripts/Configure-ScreenTurn.sh`，模板为 `relay/coturn.conf.example`。它只使用现有 ECS；`--prepare` 仅生成服务器私有文件。`--enable-public` 才安装并启用服务，必须在域名备案、HTTPS 证书和新增公网规则的审核完成后执行。脚本不会操作阿里云安全组。

```bash
export VB_TURN_REALM=voicebridge-room.cn
export VB_PUBLIC_IP=121.196.145.43
export VB_PRIVATE_IP=172.30.161.52
sudo -E bash scripts/Configure-ScreenTurn.sh --prepare
# 公开启用前提供有效的证书/私钥路径，并完成备案及网络规则确认：
export VB_TLS_CERT=/path/to/fullchain.pem
export VB_TLS_KEY=/path/to/privkey.pem
sudo -E bash scripts/Configure-ScreenTurn.sh --enable-public
```

公网规则为 UDP/TCP 3478、TCP 5349、UDP 49160–49259；原网页 HTTPS 使用 TCP 443，后端 3000 保持本机。中继设认证、配额、带宽限制、私网与云元数据地址阻断，并关闭管理 CLI。`Configure-ScreenTurn.sh --enable-public` 会调用 `Configure-ScreenBandwidth.sh`，为中继端口设置约 5 Mbps 的实际出口合计限速；不使用按每个连接预留最大带宽的方式，避免少量连接即占满预留额度。限速脚本保留网卡原根队列和其他规则，遇到预设规则编号冲突会停止。预算按 10Mbps 服务器保留声音余量，仍需结合所有房间的实际音频流量调整容量。证书续期后应同步更新 TURN 的证书副本并在维护窗口重启 coturn；不能仅续网页证书而遗漏中继证书。

视频传输使用 WebRTC 的 DTLS-SRTP；SDP/ICE 通过原 WSS 连接转发。信令按房间、成员、共享会话和观看连接随机标识隔离，只允许当前共享者发 offer，当前观看者回答；不允许加入额外音频或数据通道。视频不进入原音频二进制包队列。服务器仍控制网页代码，不宣称抵抗恶意服务管理员。

## 发布前验收

- Node 自动测试：抢占、权限、旧连接隔离、音频兼容、取消授权、暂停与来源切换回滚、码率限制、TURN 凭据期限。
- 在 relay 目录执行 `npm run test:browser` 可启动可复现的浏览器测试服务。打开控制台给出的本机测试地址，点击“开始视频验证”。报告保存在该目录的 `artifacts/browser-test/browser-report.json`，均为合成数据，不能作为公网或真实设备实测的替代。
- 浏览器测试使用合成画布，经真实房间信令和真实 WebRTC 验证多人视频、暂停、恢复、像素来源变化及断线释放；不采集用户真实屏幕、麦克风或证件页面。
- 本次公网 HTTPS/WSS 与强制 UDP/TCP/TLS 中继均通过验证，具体证据及尚未完成的真实设备项目见 [发布验证](VERIFICATION-0.10.0.md)。人工多设备与延迟测量不能由合成测试替代。
